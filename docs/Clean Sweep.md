## ROLE

You are acting as an elite multidisciplinary product design team consisting of:

* Chief Product Officer

* UX Researcher
* UX Architect

* Interaction Designer
* Information Architect
* Design Systems Architect

Your task is to design the complete visual and user experience foundation for **ForgeHub**.

# THE OPERATING SYSTEM FOR TECHNICAL CREATION

---

# 1. THE CORE PRODUCT VISION

ForgeHub is a digital environment where technical ideas become:

```text
IDEAS
   ↓
PROBLEMS
   ↓
RESEARCH
   ↓
DESIGNS
   ↓
CALCULATIONS
   ↓
EXPERIMENTS
   ↓
PROTOTYPES
   ↓
TESTS
   ↓
FAILURES
   ↓
ITERATIONS
   ↓
RESULTS
   ↓
PROOF OF WORK
```

ForgeHub exists to make technical creation:

* Visible
* Structured
* Documented
* Discoverable
* Collaborative
* Verifiable
* Reusable

The central question the product should answer is:

> "How did this technical work come to exist?"

---

# 2. THE CORE PRODUCT THESIS

Most professional platforms focus on claims.

LinkedIn says:

> "I have this skill."

GitHub says:

> "Here is my code."

A CV says:

> "I worked on this project."

ForgeHub should say:

> "Here is the complete evidence of how I solved this problem."

The core unit of ForgeHub is therefore not the user.

It is the:

# PROJECT

The user becomes discoverable through their contribution to meaningful technical work.

---

# 3. THE MARKET FORGEHUB IS ENTERING

ForgeHub is entering the intersection of:

* Technical project management
* Engineering documentation
* Digital portfolios
* Technical collaboration
* Research documentation
* Knowledge management
* AI-assisted technical work
* Technical talent discovery

However, ForgeHub must not look like a combination of existing products.

It must establish its own category:

# TECHNICAL CREATION INFRASTRUCTURE

The product should feel like a new environment designed specifically for the way technical ideas are developed.

# 5. THE CORE EXPERIENCE

A user should not feel like they are simply filling in forms.

They should feel like they are entering a:

# DIGITAL ENGINEERING WORKSHOP

The experience should feel like:

* A laboratory
* A workshop
* A technical command centre
* A blueprint
* A research notebook
* A version history
* A living map of an idea becoming real

The interface should make the user feel:

> "I am building something."

Not:

> "I am managing another project management board."

# 6. THE PROJECT AS A LIVING OBJECT

A ForgeHub project is not a folder.

It is a living technical object.

Every project should have:

* A history
* Versions
* Decisions
* Evidence
* Experiments
* Contributors
* Dependencies
* Failures
* Results

The visual experience should communicate that a project evolves over time.

Example:

```text

   ↓

   ↓
TEST FAILURE
   ↓
DESIGN CHANGE
   ↓
VERSION 02
   ↓
IMPROVED PERFORMANCE
   ↓
VERSION 03
```

This evolution should be visually meaningful.

# 8. THE SIGNATURE EXPERIENCE: THE PROJECT MAP

The most important visual feature of ForgeHub should be the:

# PROJECT MAP

Do not make the main project experience look like a conventional dashboard.

Instead, create an interactive visual map of the project.

Example:

```text
                 PROBLEM
                    │
                    ▼
                RESEARCH
              ↙     │     ↘
        MATERIALS  DESIGN  EXISTING
                    │      SOLUTIONS
                    ▼
                CALCULATIONS
                    │
                    ▼
                 PROTOTYPE
                    │
                    ▼
                  TESTING
                ↙         ↘
             FAILURE      RESULT
                │           │
                └─────┬─────┘
                      ▼
                  ITERATION
                      │
                      ▼
                  VERSION 2
```

The map should be:

* Interactive
* Zoomable
* Navigable
* Visually intelligent
* Contextual
* Able to grow as the project grows

Each node should represent a meaningful piece of technical work.

Clicking a node should reveal:

* Documentation
* Files
* Contributors
* Evidence
* Decisions
* AI insights
* Related nodes

This should become one of ForgeHub's most distinctive experiences.

# 11. EVIDENCE AND PROOF OF WORK

ForgeHub must visually distinguish between:

## CLAIMS

> "I know CAD."

and:

## EVIDENCE

> "Here is the CAD model I designed, the design decisions I made, the iterations I completed, and the final result."

Design a system that allows technical work to be connected to evidence.

Examples:

```text
DESIGN DECISION
      ↓
CALCULATION
      ↓
CAD MODEL
      ↓
PROTOTYPE
      ↓
TEST RESULT
```

The UI should make these connections visible.

A project should communicate not just:

> "This is what we built."

but:

> "This is why we built it, how we built it, what went wrong, and what proves the final result."

---

# 12. FAILURE AS A FIRST-CLASS OBJECT

This is a major part of ForgeHub's identity.

Most platforms showcase only successful results.

Engineering is built on failure.

ForgeHub should allow users to document:

```text
ATTEMPT 01
FAILED

WHY?
Excessive vibration

OBSERVATION
Frame resonance occurred at operating speed

CHANGE
Increased frame stiffness

RESULT
Vibration reduced by 42%
```

Create a visually meaningful system for:

* Failed experiments
* Design revisions
* Lessons learned
* Performance changes

Failure should not look like an error message.

It should look like:

# ENGINEERING PROGRESS

# 14. THE AI EXPERIENCE

Do not design the AI as a generic chat window.

The AI should be:

# THE PROJECT INTELLIGENCE LAYER

The AI should understand the project context.

It should be able to identify:

* Missing documentation
* Contradictions
* Unresolved decisions
* Incomplete project stages
* Potential next steps
* Connections between project components

Example:

```text
PROJECT INTELLIGENCE

⚠ Your design requirements specify:
Maximum weight: 15 kg

Current CAD estimate:
18.4 kg

RECOMMENDATION:
Review the frame material selection.
```

Another example:

```text
PROJECT INSIGHT

You have completed:
✓ Problem Definition
✓ Research
✓ Concept Design

Incomplete:
⚠ Testing Methodology

Suggested next action:
Define measurable testing criteria.
```

The AI should feel like an intelligent layer over the project, not an isolated chatbot.
